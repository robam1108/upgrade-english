# UPGRADE ENGLISH — 영어학원 랜딩페이지

초·중등 영어학원을 위한 반응형 랜딩페이지입니다.
학부모가 페이지에 들어와 **학원을 이해하고 → 신뢰하고 → 상담을 신청하기까지**의 흐름을 하나의 스크롤 안에 설계했습니다.

> 포트폴리오용 가상 브랜드입니다. 학원명·주소·연락처·강사 정보는 모두 실제가 아니며, 상담 폼은 실제로 전송되지 않는 데모입니다.

<br>

## 프로젝트 배경

기존에 만든 같은 학원의 랜딩페이지(v1)를 **"Bright Editorial Education"** 콘셉트로 다시 디자인하고, 실제 납품 수준으로 다듬은 버전입니다.

- 학원 홈페이지가 흔히 쓰는 원색·배너 위주의 디자인 대신, 아이보리 바탕에 하늘색·버터 옐로·네이비를 쓰는 **잡지형(에디토리얼) 레이아웃**으로 차분하고 신뢰감 있는 인상을 주도록 했습니다.
- 주 방문자인 학부모는 대부분 **모바일**로 들어온다는 점을 전제로, 모바일 화면을 먼저 설계하고 데스크톱으로 확장했습니다.
- 겉모습뿐 아니라 **로딩 속도, 접근성, 검색 노출**까지 실제 운영되는 사이트 기준으로 챙겼습니다.

<br>

## 페이지 구성

| 순서 | 섹션 | 역할 |
| --- | --- | --- |
| 01 | Hero | 핵심 메시지와 상담 신청 버튼 |
| 02 | 학원 소개 | 교육 철학, 소수정예 수업 강조 |
| 03 | 교육 과정 | 초등부 / 중등부 커리큘럼 |
| 04 | 학습 시스템 | 개념 → 복습 → 점검 → 피드백 단계 |
| 05 | 강사진 | 대표 강사 및 강사 소개 |
| 06 | 학습 공간 | 강의실·자습실·상담실 사진 갤러리 |

모든 섹션은 `(01) Our Philosophy ———` 형태의 공통 섹션 마크로 시작해, 섹션마다 레이아웃이 달라도 하나의 흐름으로 읽히도록 했습니다.

## 주요 작업 포인트

### 1. 디자인 시스템

색상·타이포그래피·간격을 Tailwind CSS v4의 `@theme` 토큰으로 정의하고, 모든 컴포넌트가 이 토큰만 쓰도록 했습니다. 색이나 글자 크기를 바꿀 때 한 곳만 고치면 됩니다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `ivory` | #F7F8F3 | 기본 배경 |
| `sky-soft` | #DCEFFA | 보조 배경 |
| `sky` | #91C8E7 | 포인트 면·선 |
| `butter` | #F5D77E | CTA, 강조, 상담 섹션 배경 |
| `navy` | #263B50 | 본문, 버튼, 어두운 섹션 배경 |
| `warm-gray` | #E9E8E1 | 교육 과정·FAQ 배경 |

- 텍스트 색은 실제로 놓이는 배경 위에서 **명도 대비 4.5:1 이상**(WCAG AA)이 되도록 맞췄습니다.
- 타이포그래피는 `display → h2 → h3 → lead → body → small → eyebrow` 7단계로 제한해 페이지 전체의 위계를 일정하게 유지했습니다.

### 2. 성능 최적화

**한글 웹폰트 서브셋 자동화** — 한글 가변 폰트(SUIT)는 원본만 600KB가 넘습니다. 소스 코드에서 실제로 쓰인 글자만 뽑아 폰트를 잘라내는 Node 스크립트를 직접 만들었습니다.

- 페이지에 쓰인 글자 조각(약 112KB)만 모든 방문자가 받습니다.
- 나머지 상용 한글 2,350자 조각은 `unicode-range`로 분리해, 상담 폼에 그 글자를 입력할 때만 내려받습니다.
- 문구를 수정하면 `npm run fonts:subset` 한 번으로 서브셋과 `@font-face` 규칙이 다시 만들어집니다.
- 첫 로드 폰트 용량: **약 165KB** (SUIT · DM Sans · 에이투지체 합계)

**이미지 파이프라인** — `sharp`로 원본 사진(장당 약 2MB)을 화면 크기에 맞춰 잘라 WebP 1x/2x로 변환하는 스크립트를 만들었습니다.

- `srcset`·`sizes`·`<picture>`로 기기 해상도와 화면 폭에 맞는 이미지만 받습니다.
- 히어로 이미지는 데스크톱(세로형)과 모바일(가로형)을 따로 잘라 각 화면에 최적화된 구도를 보여줍니다.
- 첫 화면 이미지는 `fetchpriority="high"`, 아래쪽 이미지는 `loading="lazy"`로 로딩 순서를 조절했습니다.
- 링크 공유용 OG 이미지(1200×630)도 같은 스크립트에서 생성합니다.

**지도 지연 로드** — 네이버 지도 SDK는 푸터가 화면에 가까워질 때만 불러오고, 좌표는 상수로 두어 방문할 때마다 주소 변환 API를 호출하지 않습니다.

### 3. 접근성

- 시맨틱 마크업과 `aria-labelledby`로 섹션 구조를 스크린리더가 이해할 수 있게 했습니다.
- "본문으로 건너뛰기" 링크, 키보드 포커스 표시, 모바일 메뉴의 `aria-expanded`·`aria-controls`를 적용했습니다.
- 상담 폼은 오류가 나면 **첫 번째 오류 항목으로 포커스를 옮기고**, `aria-invalid`·`aria-describedby`로 오류 문구를 입력칸과 연결했습니다. 제출 결과는 `role="status"`로 스크린리더에도 알립니다.
- 운영체제에서 "동작 줄이기"를 켠 사용자에게는 스크롤 애니메이션을 끄고 콘텐츠를 바로 보여줍니다.

### 4. 전환을 위한 UX

- **모바일 하단 고정 상담 바**: 전화 / 상담 신청 버튼을 항상 손 닿는 곳에 둡니다. 히어로나 상담 섹션처럼 같은 버튼이 이미 보이는 구간에서는 자동으로 숨겨 중복을 피했습니다.
- 아이폰 홈 인디케이터 영역(`safe-area-inset`)까지 계산해 고정 바가 콘텐츠를 가리지 않게 했습니다.
- 상담 폼은 처음 제출을 시도한 뒤부터 실시간으로 다시 검사해, 수정한 항목의 오류 문구가 바로 사라집니다.

### 5. 검색 노출(SEO)과 공유

- 카카오톡·네이버처럼 자바스크립트를 실행하지 않는 크롤러를 위해 Open Graph·Twitter 카드 태그를 HTML에 직접 넣었습니다.
- 학원 정보(`EducationalOrganization`)와 FAQ(`FAQPage`)를 **JSON-LD 구조화 데이터**로 제공합니다. 콘텐츠 데이터에서 자동으로 만들어지므로 문구가 바뀌어도 어긋나지 않습니다.
- `robots.txt`, `sitemap.xml`, canonical URL을 설정했습니다.

### 6. 유지보수를 고려한 구조

모든 문구와 목록 데이터를 `src/data/content.ts` 한 파일에 모았습니다. 학원 측에서 커리큘럼·FAQ·운영 시간 같은 내용을 바꿀 때 컴포넌트 코드를 건드리지 않고 이 파일만 수정하면 됩니다.

## 폴더 구조

```
src/
├─ components/          섹션 단위 컴포넌트 (Header → Footer 순서)
│  └─ ui/               SectionMark, ButtonLink 등 공통 UI
├─ data/content.ts      모든 문구·목록 데이터
├─ assets/              생성된 WebP 이미지, 서브셋 폰트
├─ fonts.css            자동 생성된 @font-face 규칙
└─ index.css            디자인 토큰(@theme)과 유틸리티
scripts/
├─ subset-fonts.mjs     웹폰트 서브셋 생성
└─ build-images.mjs     이미지 리사이즈·WebP 변환, OG 이미지 생성
```

## 로컬 실행

```bash
npm install
npm run dev        # http://localhost:5174
```

| 스크립트 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm run build` | 타입 체크 후 프로덕션 빌드 |
| `npm run preview` | 빌드 결과 미리보기 |
| `npm run lint` | oxlint 검사 |
| `npm run fonts:subset` | 웹폰트 서브셋 재생성 (문구 수정 후 실행) |
| `npm run images:build` | `assets-source/` 원본 사진으로 WebP·OG 이미지 생성 |

### 네이버 지도 (선택)

```bash
# .env
VITE_NAVER_MAP_CLIENT_ID=발급받은_키
```

키가 없어도 지도 자리에 안내 화면이 표시되고 나머지 페이지는 정상 동작합니다.
`VITE_` 값은 빌드 결과물에 포함되므로, 네이버 클라우드 콘솔에서 서비스 도메인을 꼭 등록해야 합니다.

## 실제 운영 시 추가로 필요한 작업

이 프로젝트는 포트폴리오용이라 아래 항목은 의도적으로 제외했습니다. 실제 납품 시에는 함께 진행합니다.

- 상담 폼 전송 백엔드(이메일·문자·스프레드시트 연동 등)와 스팸 방지
- 개인정보 수집·이용 고지(수집 항목·목적·보유 기간)
- 전환 추적(GA4, 네이버 애널리틱스, 광고 픽셀 등)
- 실제 도메인 연결 및 OG·canonical URL 교체
